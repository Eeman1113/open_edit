# Open_Edit build brief (for contributors and agents)

Open_Edit is an **original, open-source** web camera and photo/video editor. It is a clean-room product with its own identity. It must contain nothing taken from any vendor app's package: no images, icons, filter tables, shaders, textures, warp tables, layout measurements copied as a "look", UI text, or brand names.

## What we keep (our own code, or code we're allowed to use)
- The engines and the feature set: live camera with WebGL filters, face tracking (MediaPipe, Apache-2.0), face reshape, makeup and AR stickers, the photo editor tools, the video editor, collage, gallery (IndexedDB), and the on-device AI tools: MI-GAN (MIT), Real-ESRGAN (BSD-3), Depth Anything V2 Small (Apache-2.0), onnxruntime-web (MIT).
- Workflows and functionality. Features and workflows aren't owned by anyone, so camera → confirm → edit → save etc. stay.

## What must be original
- **Visual design:** our own design system: name, logo, colour palette, typography (use open fonts such as Inter or Space Grotesk, loaded under the OFL), spacing, component shapes and screen layouts. Don't reproduce another app's trade dress. Don't keep measured pixel values and just recolour them; design it fresh.
- **Icons:** `lucide-react` (ISC), or our own SVGs. No vendor drawables.
- **Text:** write every user-visible string in our own words, in clear English.
- **Assets:**
  - Filter colour tables: generate them procedurally from documented colour grades we define.
  - Makeup and stickers: procedural, or our own original art.
  - Skin-tone tables, brushes, collage layouts, sample media and demo content: generated by our own scripts in `scripts/`.
- **Shaders and warp data:** write them ourselves. Use parametric face warps built from MediaPipe landmarks, not vendor tables.
- **Code comments:** no references to vendor class names, decompiled code, or the old app.

## Product rules
- **No login or accounts anywhere.** Every session is a fresh anonymous user. Local data (gallery, settings) lives only in the browser and can be cleared from Settings.
- **No paywalls or premium tiers.** Everything is free.
- **Server-backed features** (content catalogs such as music, stickers and templates): go through Next.js route handlers in `src/app/api/**`, which read provider URLs and keys from server-side env vars (`.env.example`). Never expose secrets to the client. With no provider configured, ship a built-in local catalog from `public/content/**` so every feature works out of the box.

## Asset packs (swappable assets)
Every replaceable asset is loaded through one **asset pack**, never by hard-coded path. This lets a differently licensed pack be dropped in later without code changes. Replaceable assets are icons and illustrations, filter tables, skin and whitening tables, makeup textures, sticker art, brush tips, collage layouts, demo content, fonts and brand marks.
- **Manifest:** `src/lib/assets/` defines a typed manifest interface plus `getAsset(kind, id)` and `useAsset(kind, id)`, which return URLs through `asset()`.
- **Default pack:** the built-in "open" pack lives in `public/packs/open/` with `manifest.json`, and contains only original or permissively licensed assets.
- **Choosing a pack:** the active pack is set by `NEXT_PUBLIC_ASSET_PACK` (default `open`). Packs other than `open` are git-ignored (`public/packs/*` except `open`) and must never be committed to the public repo.
- **No hard-coded paths:** UI code, filters, face, stickers, brushes and collage must look assets up by kind and id through the manifest.
- **Verification:** the provenance audit scans only `public/packs/open` plus the rest of the repo.

## Dependencies
- Adding a package (`npm install <pkg>`) can briefly break the running dev server. After any install, check that `node_modules/next/dist/server/lib/start-server.js` exists and that http://localhost:3700 returns 200. If the server died, tell the lead instead of starting another server.
