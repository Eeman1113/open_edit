# Engines, generated assets and the asset pack

This document covers the rendering engines (`src/lib/gl`, `src/lib/face`), the data that drives them
(`src/data`) and every generated asset they use. All of it is original: colour grades, shaders, face warps,
makeup, stickers, brushes, layouts, demo content and sample media are defined in code in this repository and
generated by the scripts in `scripts/`. The only third-party inputs are the MediaPipe face mesh topology and
canonical UV layout (Apache-2.0) and OFL-1.1 fonts.

## Asset packs

Replaceable assets are never loaded by hard-coded path. They live in an **asset pack**: a folder
`public/packs/<id>/` with a `manifest.json`, looked up by kind and id.

```ts
import { getAsset, useAsset, getAssetMeta, listAssets, hasAsset } from "@/lib/assets";

getAsset("filter", "warm-film");          // URL of the warm-film lookup table
useAsset("icon", "camera");               // same, in a component (re-renders when a custom pack loads)
getAssetMeta("sticker", "cat");           // the sticker definition stored in the manifest
listAssets("collage");                    // ["grid-2", ..., "grid-9"]
```

- **Manifest** (`src/lib/assets/types.ts`): `{ name, title, version, license, kinds: { <kind>: { <id>: { path, type?, license?, meta? } } } }`.
  `path` is relative to the pack folder (folders end with `/`). `meta` carries data the consumer needs (names,
  default strengths, sticker definitions, layout rects, font families...).
- **Kinds** (open-ended, `AssetKind`): `filter`, `filter-thumb`, `table`, `makeup`, `sticker`, `sticker-thumb`,
  `brush`, `collage`, `feed`, `video`, `font`, `music`, `root`, plus the design system's `icon`, `brand`, `illustration`,
  `theme`. A pack may add kinds; code that does not know a kind never asks for it.
- **Choosing a pack**: `NEXT_PUBLIC_ASSET_PACK` (default `open`). The open pack's manifest is bundled, so lookups
  are synchronous from the first render. Another pack's manifest is fetched at startup and takes over; ids it does
  not provide fall back to the open pack. `useAsset` / `useAssetPack` re-render when it arrives.
- **Licensing**: only `public/packs/open` is committed. Other packs are git-ignored (`.gitignore`), so a pack
  under a different licence can be dropped in locally or at deploy time without code changes.

## Regenerating

```sh
source ~/.nvm/nvm.sh && nvm use 24
node --no-warnings scripts/gen-all.mjs        # everything, in dependency order
node --no-warnings scripts/gen-luts.mjs       # or one generator at a time
```

Generators are deterministic (seeded PRNG), so a rerun produces the same files. Each one replaces only the manifest
kinds it owns and keeps the rest (icons and brand marks are added by the design system). The scripts import the
plain-data TypeScript catalogues in `src/data` directly (Node 24 strips the types).

| script | output (in `public/packs/open/`) | manifest kinds |
| --- | --- | --- |
| `gen-luts.mjs` | `filters/<key>.png`, `filters/thumbs/<key>.png`, `tables/*.png` | `filter`, `filter-thumb`, `table` |
| `gen-stickers.mjs` | `stickers/<slug>/*.svg` | `sticker`, `sticker-thumb`, `root/stickers` |
| `gen-brushes.mjs` | `brushes/<id>.png` | `brush` |
| `gen-collage.mjs` | `collage/grid-<n>.json` | `collage` |
| `gen-fonts.mjs` | `fonts/<id>.woff2`, `fonts/<id>-OFL.txt` | `font` |
| `gen-music.mjs` | `music/<id>.mp3` (8 synthesised loops; WAV if ffmpeg is missing) | `music` |
| `gen-feed.mjs` | `feed/*.svg`, `videos/clip-*.mp4` / `.jpg`, plus `src/data/home.json`, `src/data/discover.json` | `feed`, `video` |

Shared helpers: `scripts/gen-lib/png.mjs` (dependency-free PNG encoder), `scripts/gen-lib/grade.mjs` (colour-grade
operations), `scripts/gen-lib/pack.mjs` (pack paths, manifest merging, seeded PRNG).

## Filters

- **Catalogue**: `src/data/filters.ts` (key, numeric id for deep links, name, group, default strength, one-line
  description). `src/lib/filters.ts` turns it into `LOCAL_FILTERS` and keeps the helper API (`filterByKey`,
  `lutFor`, `strengthFor`, `galleryStrengthFor`, `CAMERA_BASIC_ORDER`, `EDIT_BASIC_ORDER`, ...). `ORIGINAL` is the
  pass-through entry.
- **Looks**: `LOOKS` in `scripts/gen-luts.mjs` defines each grade as a list of operations from
  `gen-lib/grade.mjs`: exposure, white balance (temp / tint), luma S-curve contrast, saturation, vibrance,
  lift / gamma / gain, fade (black / white point), luma-masked split toning, monochrome channel mix with toning,
  master and per-channel monotone cubic curves, hue-band shifts, highlight roll-off.
- **Table format**: 512x512 PNG, 8x8 slices of 64x64; slice index = blue level, x = red, y = green.
- **Sampling**: `CUBE_GLSL` in `src/lib/gl/editShaders.ts` (two bilinear fetches blended along blue = trilinear).
- **Swatches**: every look is also applied to a procedural 120x120 test scene (sky, sun, hills, sand, a flower, a
  skin-tone patch and a grey ramp) to make `filters/thumbs/<key>.png`.

22 looks: Natural, Clean, Bright, Peach, Cream, Mint, Warm Film, Cool Matte, Fade, Retro, Golden, Instant, Dusk,
Cinema, Ocean, Forest, Lilac, Rose, Mono, Noir, Silver, Sepia.

## Renderer and editor shaders

`src/lib/gl/renderer.ts`: source -> skin smoothing -> face passes -> colour cube (filter strength + brighten) ->
portrait tone -> camera adjust -> editor adjust -> canvas.

- **Skin smoothing**: an edge-aware average over two rotated rings of eight taps (colour-distance range weight),
  scaled to the output size, applied in proportion to a chroma-based skin likelihood, keeping part of the fine
  detail.
- **Brighten** (`table/whiten`): lifts midtones, cools and slightly desaturates warm tones.
- **Portrait tone**: `skin-warm` / `skin-cool` (Cool-Warm slider), `skin-light` / `skin-tan` (Tan-Light slider), and
  skin tone presets `skintone-<key>-skin` + `skintone-<key>-bg` blended by a skin likelihood mask. Presets are defined
  in `src/data/skintones.ts` (Fair, Rosy, Golden, Tan, Deep).
- **Editor adjust** (`EDIT_FRAG`): two-scale decomposition with blurred base layers at 1.5% and 4% of the short side.
  Auto tone, brilliance (adaptive shadow lift / highlight hold), brightness (luma gamma), contrast (luma S-curve),
  clarity (large-radius local contrast weighted to midtones), detail (small-radius local contrast), sharpen
  (unsharp mask), highlights / shadows (recovery driven by the base layer), white balance (warmth / tint gains on an
  approximately linear signal), vibrance / saturation, fade, curves (per channel then master), HSL (seven
  raised-cosine hue bands), split tone (luma-masked soft light), vignette, film grain (`table/grain`, tileable
  256x256 noise, weighted to midtones).

## Face engine (`src/lib/face`)

Built on the MediaPipe Face Landmarker (478 landmarks, blendshapes) and the face mesh tessellation.

- **Reshape** (`warp.ts`): purely parametric. `WarpParams` holds ~40 named controls (face, jaw, chin, temples,
  hair volume, eye size / shape / position / corners / iris, nose size / bridge / root / tip / nostrils, mouth, lips,
  cupid's bow, brows...). Each is a smooth displacement field in the face frame (contour envelope fields for the face
  shape, elliptical scale / move / rotate fields for features). `ShapeWeights` (`faceSlim_left: 0.4`) restricts a
  control to one image side with a soft midline mask. `WarpOp` adds generic local deformations, including depth-aware
  `move3d` moves used by the 3D sculpt (`beauty3dOps`). Safety: a soft displacement limit (tanh-compressed to 0.22
  eye distances), lid / lip non-crossing guards, and a fold guard (local relaxation of folded triangles, then a global
  scale-back if needed).
- **Presets** (`presets.ts`): Natural, Soft, Slim, Bright Eyes, V-line; each a set of `WarpParams` values applied at
  a strength.
- **Makeup** (`makeup.ts`): procedural region geometry from landmarks with feathered edges, composited with blend
  modes: lips (full / gradient / blurred, luminance sheen, `lipGloss` glass highlights or glitter sparkles), blush
  (apple / lifted / wide), contour (soft / sculpt), highlight, eyeshadow (lid / crease / smoky), eyeliner (thin / wing /
  cat / lower), brows (natural / soft / bold), iris tint (procedural fibres, limbal ring and clear pupil; ring /
  starburst / solid), catchlights (dot / soft / ring / window / star / twin), beauty marks, retouch (teeth and eye
  whites, dark circles, smile lines). Textures in MediaPipe canonical face UV or anchor mappings remain supported for
  pack art.
- **3D lashes**: `lash3d` builds a procedural strip per lid: strands rooted along the lid by arc length, grown away
  from the eye and toward the camera, curled upward, fanned toward the outer corner, projected with the head pose;
  each strand is a tapered ribbon shaded as a soft hair. Options: length, density, curl, flare, lower lashes.
- **Stickers** (`sticker.ts`, format in `STICKER_FORMAT.md`): face-anchored 2D / 3D sprites, image sequences and
  sprite sheets, expression triggers, face-UV masks, procedural iris tints, segmentation backgrounds, a procedural
  ellipsoid head occluder, and sticker-level reshape / makeup presets.

## Generated content

- **Stickers** (`gen-stickers.mjs`): Sparkles (twinkling sequence), Hearts (floating sequence + blush), Kitty
  (3D ears behind a head occluder, nose and whiskers), Shades (3D sunglasses), Glitter (face-UV sparkles + glitter
  lips), Mesh scan (face-UV wireframe of the tessellation with a sweeping band), Freckles (face-UV), Sky lens / Amber
  lens (procedural iris tints), Starlight eyes (catchlight), Glam (makeup preset), Doll lashes (3D lashes), Big eyes
  (reshape preset), Dreamy sky (background replacement), Mouth pop (mouth-open trigger). All art is SVG drawn by the
  script; face-UV textures are drawn on the MediaPipe canonical UV layout.
- **Makeup catalogue**: `src/data/camera/beauty.ts` (`MAKEUP_CATEGORIES`): colour, style and blend per look, shared
  by the camera and the photo editor.
- **Brushes** (`gen-brushes.mjs`): round, soft, marker, marker-soft, neon, dashed, spray (128x128 white tips, alpha =
  coverage).
- **Collage layouts** (`gen-collage.mjs`): for 2..9 photos; rows and columns from every composition of n into up to
  four rows, feature layouts (one large cell + strip), uneven pairs, mosaics; deduplicated, at most 12 per count.
  `src/components/collage/layouts.ts` reads them from the pack.
- **Fonts** (`gen-fonts.mjs`): Inter and Space Grotesk from `@fontsource-variable`; Playfair Display, Caveat,
  Pacifico, Bebas Neue and DM Mono from Google Fonts, each with its OFL.txt. `src/lib/fonts.ts` registers them.
- **Demo feed** (`gen-feed.mjs`): abstract generative artwork (waves, orbs, rings, blocks, stripes, dunes, dot grids
  on gradient palettes), home groups (banners, shortcuts, effects, filters, chart, face styles) and discover posts by
  fictional accounts ("Open_Edit Team", "Palette Studio", ...). No real people, brands or social accounts.
- **Sample video**: two 6 s 720x1280 H.264 clips rendered by ffmpeg from its synthetic `gradients` source, with
  poster frames.

## Adding or replacing assets

- New look: add it to `src/data/filters.ts` and `LOOKS` in `gen-luts.mjs`, run the script.
- New sticker: add a `def(...)` in `gen-stickers.mjs` (art + definition), run the script; it appears in every
  sticker panel through `src/data/camera/stickers.ts`.
- Custom pack: create `public/packs/<id>/manifest.json` with the kinds / ids to override, set
  `NEXT_PUBLIC_ASSET_PACK=<id>`. Anything not listed falls back to the open pack.

### Effects (gen-effects.mjs)
`scripts/gen-effects.mjs` generates the overlay textures (light leak, dust, bokeh) used by the photo and video Effects tabs. They are registered under the `fx` asset kind. The effect shaders live in `src/lib/gl/effects.ts`.
